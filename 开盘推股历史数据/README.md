# 开盘推股历史数据

盘中「开盘推股名单」的推送记录，由 **skapp-app 端上实时提交**，供云端 11:40 的午盘名单（`scripts/build_picks_midday.py`）读取。

## 文件

一天一个：`YYYY-MM-DD.json`（北京时间日期）。同一时刻只保留最新一轮写入，收盘后补一轮 `mode=final`。

## 结构

```json
{
  "date": "2026-10-29",
  "source": "skapp-app",
  "app_version": "2.2.0",
  "rounds": [
    {
      "ts": "2026-10-29T09:31:00+08:00",
      "mode": "open",
      "base": ["600001", "600002"],
      "picks": [
        {
          "code": "600000",
          "name": "浦发银行",
          "score": 87.5,
          "tags": ["量比 2.1", "主力净流入 3200 万"],
          "data": {"pctChg": 3.2, "turnover": 1.8, "amount": 510000000}
        }
      ],
      "note": "早盘名单 3 只中 2 只维持，新增 1 只"
    }
  ]
}
```

字段约定：

- `rounds[].mode`：`open`（盘中轮次）/ `final`（收盘补记）
- `rounds[].base`：早盘推股名单里的代码（这次计算的基础）
- `rounds[].picks[].data`：这一轮实际用的行情字段（涨幅、换手、成交额），便于事后复核「当时为什么推」
- `rounds[].note`：与前一轮相比的变化说明

## 写入规则

- 盘中每 5 分钟最多写一次（节流），避免把仓库刷成流水账
- 单文件按天累积，不删历史轮次（午盘与收盘复盘都要用）
- 端上没开/没网时允许缺文件：午盘脚本会降级并在 `caveats` 里写明「无盘中数据」，不编造

## 谁读

- `scripts/build_picks_midday.py`（11:40）——按「被推轮次 + 最新得分」排序出午盘名单
- 收盘后的 A/B 候选（`build_picks_daily.py`）暂不读它，留给后续「用当天实际推送质量校准」用
