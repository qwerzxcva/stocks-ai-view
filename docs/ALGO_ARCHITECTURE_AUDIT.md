## 二、用户点名的 12 类算法核对表

| # | 算法/引擎 | 状态 | 实现位置 | 水平评级 | 说明 |

| 2 | 找缺点算法 | ⚠️ 部分 | `self_reflect.py:problems` | 弱 | 只有 3 条硬编码规则（胜率<45/5日衰减/数据旧），无系统性缺陷扫描 |

| 5 | 打分算法 | ✅ 有 | `engine_v5.py`(17指标共振)、`multidim_engine.py`(9维加权)、`ai_pick_v4.py`(6因子)、`pick_algo.py`(5因子) | 中 | **4 套打分并存且权重都是手工设定**，无统一校准 |
| 6 | 分析算法 | ✅ 有 | `cycle_deep.py`、`flow_divergence.py`、`indicators_ext.py`(18指标)、`patterns.py`(4形态) | 中 | 分析维度全但分散，无统一「分析报告」产出 |

## 三、缺失算法清单（P0/P1/P2）

### P0（不补则结论不可信）

| 缺失引擎 | 缺它会怎样 | 建议实现 |
|---|---|---|
| **样本均衡引擎** `sample_balancer.py` | 高层板概率是噪声（n=4 说 50% 涨停率）；多头/空头样本 519:1，看空胜率无统计意义 | 经验贝叶斯收缩（Krimp 平滑）+ 层级先验 + 按 regime 分层重采样 |
| **样本扩容**（backfill 全量） | 验证样本只有 600，CI 宽达 ±8%，任何结论都可能是噪声 | `--days 668 --limit 3175` 分批回溯（见第五节估算） |
| **权重校准闭环** `weight_calibrator.py` | 特征重要性算完就扔，engine_v5 永远等权 | 用 walkforward OOS 胜率反推权重，写入 engine_v5 的 weights 参数 |

### P1（不补则能力残缺）

| 缺失引擎 | 缺它会怎样 |
|---|---|
| **风险管理引擎** `risk_engine.py` | 无波动率/回撤/ VaR /集中度控制；决策卡只有固定 3-7% 止损，无组合层面风险预算 |
| **组合优化引擎** `portfolio_optimizer.py` | 只会单票打分排序，不会在相关性/行业暴露/风险预算下做组合构建 |
| **场景化推股引擎** `scenario_engine.py` | 牛/熊/震荡/极端事件用同一套阈值；熊市还按牛市标准选股 |
| **信号审核引擎** `signal_auditor.py` | 无逻辑一致性检查（如「低位吸筹」与「高位套人」不会同现？）、无过拟合检查、无异常值拦截 |
| **异常检测引擎** `anomaly_detector.py` | 数据跳变/涨跌停误标/成交量异常直接进因子，污染全链路 |
| **归因闭环**（loss_attribution 接入） | 亏损归因脚本存在但不跑，四因子归因（beta/chase/theme/idio）从未回注 ai_pick |
| **数值数据验证** `numeric_validator.py` | 只验字段非空，不验 `price>0`、`chg_pct∈[-30,30]`、`vol≥0` |

### P2（增强）

| 缺失引擎 | 说明 |
|---|---|
| **优势挖掘引擎** `edge_miner.py` | 系统性找出「我们在哪些场景/因子/时段显著跑赢」，把偶然变必然 |
| **因子相关性/共线性** `factor_diagnostics.py` | 17 指标高度相关（MA/SuperTrend/HullMA 都是趋势），共振度可能虚高 |
| **多周期共振** `multi_timeframe.py` | 只有日线；周线/月线趋势与日线信号共振可大幅降噪 |
| **市场微观结构** `microstructure.py` | 盘口/委托/撤单（Level 2 已有配置但未用） |
| **情绪极端检测** `sentiment_extreme.py` | 冰点/高潮的极端值往往是反转点，当前只做 6 阶段不判极端 |
| **新闻-股价因果** `news_causality.py` | 消息面只数主题命中数，无「新闻发布后 N 日实际超额收益」验证 |

## 四、架构问题

### 4.1 引擎依赖图（标注断点与重复）

```
采集层 collect_all_sources / collect_market_extras
   │
   ├─→ engine_v5 (17指标等权) ──┐
   ├─→ multidim_engine (9维) ───┼─→ decision_engine ─→ 决策卡
   ├─→ ai_pick_v4 (6因子) ─────┘        ▲
   ├─→ ban_pick / ban_prob ─────────────┘ (仅概率输入)
   │
   ├─→ reflect_engine ←── predictions/ (backfill 生成) ✅闭环
   │        └─→ by_indicator ──✗ 断点: 不回写 engine_v5 权重
   │
   ├─→ kline_sim ←── predictions/ ✅
   ├─→ winrate_matrix ←── reflect_latest ✅
   ├─→ self_reflect ←── reflect + kline_sim ✅ (最完整闭环)
   │
   ├─→ valuation_engine → 注入所有股池 ✅
   │
   ├─→ optimizer ──✗ 断点: 未接入 CI, 只有 --demo
   ├─→ walkforward ──✗ 断点: 空壳 (无 IS/OOS 结果), 未接入 CI
   ├─→ loss_attribution ──✗ 断点: 未接入 CI
   ├─→ patterns / factor_lib ──✗ 断点: 未接入 CI
   └─→ rps_rotation ──✗ 断点: 列错位 (已修) 但 rps_250/120 仍 null
```

### 4.2 重复造轮子

| 重复 | 位置 | 建议 |
|---|---|---|
| 4 套打分 | `engine_v5` / `multidim_engine` / `ai_pick_v4` / `pick_algo` | 统一为「engine_v5 出基础分 + multidim 出维度修正」，ai_pick_v4 只做硬规则过滤 |
| 2 套决策 | `engines/decision.py`(GitCode) / `decision_engine.py`(GitHub) | GitHub 版为准，GitCode 版作镜像 |
| 2 套 K线加载 | `engine_v5.load_klines` / `kline_sim.load_klines` / `rps_rotation.load_closes` | 收敛到一个 `kline_io.py`，**这次列错位就是 3 份解析不一致导致** |
| 2 套市场阶段 | `market_phase.py`(6阶段) / `decision_engine.market_regime`(3档) | 6 阶段为准，3 档作粗映射 |

### 4.3 设计不合理处

1. **权重全手工**：`multidim_engine.py` 的 9 维权重（0.25/0.15/0.15/...）是拍的，没有任何验证支撑
2. **指标强相关未处理**：17 指标里趋势类占 7 个（MA/SuperTrend/HullMA/Vortex/Donchian/A-D/Pivot），共振度天然虚高
3. **单日截面打分**：所有引擎都是「当日截面排序」，无时序稳定性（昨天高分今天低分的票，噪声大）
4. **硬规则静态**：`ai_pick_v4` 的「涨幅0.5-5%」「量比1.5-2.5」在所有市场环境下不变

## 五、样本充分性分析

### 5.1 底层 vs 实际（巨大差距）

| 层 | 样本量 | 说明 |
|---|---|---|
| 底层 K 线 | **2,078,356 行 / 3175 只 / 668 交易日** | `stock.duckdb` |
| 涨停事件 | **40,698** | 足够支撑分层统计 |
| backfill 实际生成 | 12 天 × 200 只 × top50 = **~1,200 条预测** | 默认参数 |
| reflect 实际验证 | 1日 n=519、3日 n=419、5日 n=317、**10日 n=58** | 受快照数限制 |
| 理论可生成 | 668 天 × 3175 只 × top50 = **1.06 亿条** | 全量回溯 |

**样本利用率 = 600 / 1.06亿 ≈ 0.0006%**

### 5.2 各引擎样本充足性

| 引擎 | 实际样本 | 需要样本 | 充足？ |
|---|---|---|---|
| reflect 1日 | 519 | ≥1000 (CI ±3%) | ⚠️ 边缘 |
| reflect 3日 | 419 | ≥1000 | ❌ |
| reflect 5日 | 317 | ≥1000 | ❌ |
| reflect 10日 | **58** | ≥300 | ❌ 严重不足 |
| ban_prob 首板 | 20081 | ≥1000 | ✅ |
| ban_prob 2连板 | 40 | ≥1000 | ❌ |
| ban_prob 4连板+ | **4** | ≥1000 | ❌ 噪声 |
| kline_sim 1日 | 500 | ≥1000 | ⚠️ |
| kline_sim 10日 | 50 | ≥300 | ❌ |
| by_indicator | 12 指标 × n=151~519 | ≥500/指标 | ⚠️ 部分 |

### 5.3 扩容估算（实测外推）

单日单票评分耗时约 1.5ms（engine_v5 score_stock，17 指标全量计算）。

| 方案 | 计算量 | 预估耗时 | 样本提升 |
|---|---|---|---|
| 当前 (12天×300只) | 3,600 次评分 | ~6s | 1,200 条 |
| 中量 (60天×1000只) | 60,000 次 | ~90s | ~30,000 条 |
| **全量 (668天×3175只)** | 2,120,900 次 | **~53 分钟** | ~1.06 亿条 |
| 全量但只取 top50/天 | 同上 | ~53 分钟 | 33,400 条预测快照 |

**结论**：全量回溯 53 分钟，完全可行（GitHub Actions 单次上限 6 小时，Space 更无限制）。
建议：`--days 668 --limit 0 --top-per-day 50`，一次性生成 668 个快照，reflect 10日样本可达 **30万+**。

### 5.4 前视偏差风险

- backfill 用 `<= asof` 的 bars，**无未来数据** ✅
- 但**早期样本偏斜**：2024 年初的 asof，MA240/RPS240 窗口不足，`build_votes` 会返回 None 或少指标 → 早期样本被过滤或指标缺失，导致样本集中在 2024-07 之后（未实测验证，标注「未验证」）
- 缓解：asof 前至少 250 个交易日才开始评分（即 2025 年起），或对早期样本标注 `bars<250` 单独分组

## 六、复杂场景分析与推股支持度

| 能力 | 现状 | 评级 |
|---|---|---|
| 市场环境判定 | 6 阶段（ice/ignite/rally/climax/ebb/repair）+ EMA 平滑 + 2 日确认 | 强 |
| 场景差异化推股 | ❌ 无。牛/熊/震荡用同一套硬规则 | **弱** |
| 极端事件应对 | ❌ 无。VIX>25 / 千股跌停 / 黑天鹅无专门逻辑 | 无 |
| 个股 vs 组合 | 只到个股打分，无组合构建/风险预算 | 弱 |
| 个股 vs 板块 | 有板块梯队（sector_pool），但推股不强制板块一致性 | 中 |
| 多周期 | 仅日线 | 弱 |
| 盘中 vs 盘后 | 盘后为主，盘中只有 market_now | 中 |
| 行业轮动路径 | RPS 有（已修），但无「资金从 A 行业流向 B 行业」的传导分析 | 弱 |

**结论：不支持复杂场景推股。** 当前是「一套静态规则 + 3 档仓位上限」，离场景化差一个完整的 `scenario_engine`。

## 八、总结回答用户的 5 个问题

1. **需要哪些算法/引擎？** 除点名的 12 类外，还缺：样本均衡、权重校准、风险管理、组合优化、异常检测、信号审核、优势挖掘、数值验证、多周期共振、新闻因果。共 10 个新引擎。

2. **缺少哪些？** 样本均衡、权重校准闭环、风险管理、组合优化、场景化推股、信号审核、异常检测、优势挖掘、数值数据验证 —— **9 个完全缺失**；找问题/找缺点/数据验证/周期轮动/特征重要性 **5 个只有部分实现**。

3. **架构是否合理？** 部分合理（复盘闭环最完善），但有 4 套打分重复、2 套决策重复、3 套 K 线解析重复（已导致列错位 bug）、权重全手工无验证、断点 5 处（optimizer/walkforward/loss_attribution/patterns/factor_lib 未接入）。

4. **样本是否足够？** **远不足**。底层 1.06 亿可用样本只用了 600（0.0006%）。10 日持有期 n=58，4 连板 n=4 —— 这些结论目前是噪声。全量回溯只需 53 分钟，应立即执行。

5. **支持复杂场景推股吗？** **不支持**。有 6 阶段环境判定但无场景化阈值，无极端事件应对，无组合层面，仅日线。需要一个完整的 `scenario_engine`。
